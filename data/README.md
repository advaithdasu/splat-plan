# data/

Footage, frames and trained splats go here. Everything in this folder is git-ignored except this file, so raw video never gets committed (it's large, and people can end up in it).

Each capture lives in `data/captures/<name>/`:

```
raw/video.mp4         your footage (never modified)
capture.md            notes: date, lighting, camera, settings
scale.json            optional: manual metric scale
annotations.json      optional: pixel clicks on two points a known distance apart
ground.json           optional: how far the floor is below the fitted ground plane
frames/ colmap/ splat/point_cloud.ply     generated by scripts/ingest.sh
```

## Steps

1. **Set up once** (installs ffmpeg and COLMAP with Homebrew, builds Brush into `tools/`):

   ```bash
   scripts/setup_macos.sh --dry-run   # see what it will do
   scripts/setup_macos.sh
   ```

2. **Film** using the checklist below, then copy the video to `data/captures/<name>/raw/video.mp4`.

3. **Build the splat** (frames, then COLMAP on the CPU, then Brush training on the Apple GPU):

   ```bash
   scripts/ingest.sh data/captures/<name>
   ```

   Step timings are appended to `capture.md`. COLMAP can split a video into several disconnected models (a blurry stretch or a blank wall is enough). The script uses the largest, and if that one registered fewer than 80% of the frames (`--min-registered`), it matches every pair of frames and maps again, which usually joins the pieces. Use `--dry-run` to see every command first.

4. **Set the scale.** A splat has no units. Give it one real distance:

   - `scale.json`: `{ "metric_scale": 1.234, "method": "tape measure", "notes": "" }`, where the number converts reconstruction units to meters, or
   - `annotations.json`: the pixel positions of the two ends of a known distance, clicked in at least two frames each:

     ```json
     {
       "known_distance_m": 3.0,
       "label": "two tape marks on the floor",
       "endpoint_a": [{ "image": "00006.jpg", "x": 202.2, "y": 510.8 }, { "image": "00062.jpg", "x": 656.4, "y": 751.7 }],
       "endpoint_b": [{ "image": "00006.jpg", "x": 1178.8, "y": 310.9 }, { "image": "00040.jpg", "x": 861.7, "y": 101.8 }]
     }
     ```

     Image names match the files in `frames/`. The pipeline triangulates both points from the camera poses.

   Without either file, everything still runs but is marked `UNSCALED`: the flight path has no units and no planned path is certified safe.

   Leveling puts the largest flat surface below the cameras at height 0. If the floor is plain carpet that barely reconstructs, that surface can be the desk tops instead (`ground_inlier_ratio` in `pipeline.json` is low, and the cameras sit only about 0.7 m above "ground"). Then add `ground.json` with the distance from the desks down to the floor: `{ "floor_below_fit_m": 0.74, "reason": "desk tops; standard desk height" }`. It is applied inside the same alignment transform and recorded in every report.

5. **Remove floaters.** Trained splats leave faint stray Gaussians in empty air, mostly near the cameras. They show up as haze in the viewer, and the planning verifier treats each one as solid. This writes a cleaned copy of the splat and a record of what was removed:

   ```bash
   cargo run --release -p splatplan-cli -- clean data/captures/<name>
   ```

   Only Gaussians that are both faint (opacity below 0.2) and isolated (fewer than 10 others within 10 cm) go; on the two real captures that was 5% and 15% of them. Later commands use the cleaned splat and say so in every report and certificate (`--raw-splat` to opt out).

6. **Recover the flight path.** Place 10 frames per second of the video into the same COLMAP model, then check every pose against the splat:

   ```bash
   scripts/register_all.sh data/captures/<name>                     # ~10-15 min on CPU
   cargo run --release -p splatplan-cli -- flight data/captures/<name>
   ```

   Results go to `reports/<name>/flight/flight.json`: the kept poses, the gaps, and every rejected stretch with the reason.

7. **Show it** in the browser viewer: see [web/README.md](../web/README.md).

8. **Plan paths.** `replan` plans between places the drone really was (where the video starts and ends, and every spot it hovered) and keeps up to five for the viewer. `pipeline` is the benchmark: 50 random trips, reported as statistics (`reports/<name>/`, with every certified trajectory and its certificate under `certified/`).

   ```bash
   cargo run --release -p splatplan-cli -- replan data/captures/<name>
   cargo run --release -p splatplan-cli -- pipeline data/captures/<name>
   ```

## Filming checklist

1. Even lighting. Avoid moving people and objects in frame.
2. Put **two markers a known distance apart** on the floor (tape works, 3 m is good) so you can set the scale.
3. Textured surfaces reconstruct best. Blank walls and glossy or transparent things are hard.
4. Move slowly. Cover the space with 2 or 3 passes at different heights, with a lot of overlap between views. About 200 to 400 sharp frames after selection is plenty. Look back the way you came now and then: space no camera looked through stays unknown, and flying forward the whole time leaves the space just behind the camera path unseen.
5. Keep the same camera mode for the whole video. Turn off video stabilization if you can, and note what you used in `capture.md`.
6. Follow local rules for flying (permission, airspace, no flying over people).

## Good to know

- The flight path is only as good as the poses: in rooms with repeated features (rows of identical desks) a few frames can land in the matching spot across the room. `flight` catches these by speed and by comparing a render with the video, and drops them.
- For planning, anything no camera looked *through* stays unknown and is treated as an obstacle, so plans only go where the cameras actually saw empty space.
